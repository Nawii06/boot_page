# 파일럿 홈페이지 로컬 제작 순서 및 VS Code Codex 실행 프롬프트

**국립한국교통대학교 부트캠프(AI)사업단**

버전: 1.0 / 작성일: 2026-10-14

이 문서는 제작 지시서이며 실제 구현·테스트 완료 보고서가 아니다.
확정된 요구사항은 현재 대화 기준이다. 기존 저장소의 현재 코드와 실제 자료는 아직 확인하지 않았다.

본문에는 제작 기준, 28개 화면 목록, 공통 프롬프트 1개와 단계별 프롬프트 11개, 완료 점검표를 포함한다.

## 1. 목표와 적용 범위

목표: VS Code와 Codex를 이용해 로컬에서 실행하고 실제 DB에 자료를 등록할 수 있는 파일럿 홈페이지를 완성한다.
이후 경로: 로컬 완료 → Replit 임시 Publish → Cloudflare 최종 이전.
이번 완료 범위: 로컬 설치·DB 생성·관리자 인증·자료 등록·수정·삭제·공개 조회·파일 다운로드·재실행 유지·콘텐츠 백업/복원·인수인계.
이번 제외 범위: 실제 Replit Publish, Cloudflare 계정/서비스 변경, 도메인 연결, 외부 공개.

### 확정 요구사항
- 공개 메뉴: 홈 / 사업단 소개 / 교육·참여 프로그램 / 공지·자료실.
- 공개 15개, 관리자 13개, 총 28개 화면 유형.
- 로그인 없이 공개 콘텐츠 조회와 파일 다운로드 가능.
- 일반 이용자 회원가입, 학생 계정, 학교 SSO, 온라인 신청/접수 없음.
- 관리자 전용 인증과 서버 측 권한 확인 필요.
- 진행 상태값, 모집 상태 배지, 자동 상태 전환, 상태별 필터 없음.
- 교육 운영 현황은 일반 본문·표·이미지로 게시.
- 초안·공개·비공개는 게시 여부 관리이며, 교육 진행 상태와 구별.
- 신청·서류 제출은 게시물에 안내된 기존 이메일·학교 시스템·방문 경로 이용.
- 공지, 교육정보, 제출서류 안내 및 서식 다운로드가 핵심.
- 로컬 DB에 실제 저장. localStorage나 메모리 배열만으로 DB 기능을 대신하지 않음.
- 파일도 로컬에 실제 저장하고 원본을 다운로드할 수 있어야 함.
- HWP·HWPX·PDF·DOCX는 필수 첨부 형식. 이미지 업로드는 콘텐츠 편집에 필요한 범위에서 제공.
- HWP/HWPX 브라우저 미리보기나 문서 자동변환은 이번 필수 범위가 아님.

### 디자인 기준
- 공개 화면: A안 네이비·민트 정보 중심형.
- 기본색 #17324D, 강조색 #38B2AC, 흰색 및 옅은 회색 배경.
- 민트는 강조·배경에 쓰고 작은 본문·버튼 글자의 대비는 별도로 확보.
- 메인: 절제된 AI 학습·전공·협력 연결 그래픽, 읽기 쉬운 고딕체.
- 메인 문구: 내 전공에 AI를 더하다.
- 관리자: 동일 네이비·민트 색감 + C-3의 장식 없는 좌측 메뉴·검색·표 중심 구성.
- 관리자에는 큰 홍보 배너, 통계 그래프, 실적 대시보드 추가 금지.
- 공식 로고는 실제 제공 원본만 사용. 없으면 대학·사업단 명칭을 텍스트로 표시.
- 기존 시안이 현재 프로젝트에 없으면 보았다고 가정하지 말고 위 기준으로 제작.
- 시안의 과정명·날짜·연락처·참여 조건은 공식 자료가 아님. 예시로 명시하거나 입력 대기 상태로 처리.

### 향후 운영 구성
- Cloudflare Pages: 공개·관리자 프런트 화면.
- Cloudflare Workers: 게시물과 첨부파일 API, 관리자 권한 검사.
- 게시물 DB: 미확정. Cloudflare D1은 제안된 후보.
- Cloudflare R2: 첨부파일 저장.
- 관리자 인증: 지정 계정 + 서버 권한 확인. 구체적인 운영 인증 공급자는 미확정.
- GitHub 비공개 저장소: 소스코드·설계문서·변경 이력·배포 설정 관리.
- 로컬 DB로 SQLite를 우선 검토하되, 기존 정상 동작 스택과 저장소를 먼저 확인한다.
- 로컬과 Replit, Cloudflare 사이의 자동 이관·호환을 보장하지 않는다. 서버 실행 방식, DB 접근, 파일 저장, 인증별 변경 지점을 기록한다.

## 4. 프롬프트 사용 방법

1. VS Code에서 실제 작업할 프로젝트 폴더를 연다.
2. 이 문서를 프로젝트의 reference 또는 docs 폴더에 둔다.
3. 아래 P-00 공통 프롬프트를 먼저 입력한다. 파일 첨부/열람이 가능하면 이 문서 전체를 함께 제공한다.
4. P-01부터 P-11까지 한 단계씩 입력한다. 한꺼번에 모두 실행하도록 지시하지 않는다.
5. 새 Codex 대화에서는 P-00과 작업할 단계 프롬프트를 다시 제공하고 기존 프로젝트 문서를 읽게 한다.
6. 단계가 이미 구현돼 있으면 다시 만들지 말고 실제 상태와 완료 조건을 검증한다.
7. 이 문서의 경로·명령은 설계 제안이다. 실제 선택한 도구에 맞는 실행 명령은 Codex가 구현 후 README에 확정한다.

## P-00. 공통 시작 프롬프트 — 최초 및 새 대화에 입력

첨부한 '로컬 제작 순서 및 VS Code Codex 실행 프롬프트' 문서를 읽고 그 요구사항을 작업 기준으로 삼아라.

[목표]
로컬에서 DB와 첨부파일 저장소를 갖춘 공개 홈페이지 및 관리자 페이지를 실제로 동작시키는 것이 목표다.
개발 도구는 VS Code와 Codex이며, 이후 Replit에 임시 Publish하고 최종적으로 Cloudflare Pages + Workers + 게시물 DB + R2로 이전할 예정이다.
이번 요청 단계에서는 실제 외부 배포를 수행하지 않는다.

[필수 범위]
공개 15개(PUB-01~15), 관리자 13개(ADM-01~13) 화면 유형을 구현한다.
공개 메뉴는 홈 / 사업단 소개 / 교육·참여 프로그램 / 공지·자료실이다.

게시물·교육정보·서식은 실제 로컬 DB에 저장하고 재시작 후 유지한다.

[작업 원칙]
1. 기존 AGENTS.md, README, 패키지·잠금 파일, Git 상태를 먼저 읽고 기존 작업을 보존한다.

## P-04. 관리자 인증·접근권한 구현

```text
프로젝트 기준 및 진행기록을 읽고 04단계를 진행하라.

[할 일]

- 비밀번호는 원문을 저장하지 않고 적절한 검증된 해시 방식으로 처리한다. 입력 시 채팅이나 실행 로그에 비밀번호를 노출하지 않는다.

- 로그인 시도 제한을 두고 인증 실패 원문/비밀값을 응답에 노출하지 않는다.
- 관리 화면뿐 아니라 모든 콘텐츠 변경·삭제·파일 업로드 API에 서버 권한 검사를 적용한다.
- 공개 조회에는 인증을 요구하지 않는다. 비공개 콘텐츠와 첨부는 인증된 관리자만 조회하도록 기준을 세운다.

[완료 기준]
미로그인 상태에서 변경 API 직접 호출이 실패하고, 로그인 후 허용되며, 로그아웃 후 이전 세션으로 변경할 수 없다.
브라우저의 임의 플래그 변경으로 관리자 권한을 얻을 수 없다.
관리자 생성·재설정 절차가 문서화되어야 한다. 추가 관리자 계정 관리 페이지를 임의로 만들지 않는다.
```

- 여러 콘텐츠가 참조하는 파일의 삭제·교체는 다른 링크를 손상하지 않도록 처리한다.

## P-08. 메인·교육·자료실 연결 완성

```text
프로젝트 기준 및 진행기록을 읽고 08단계를 진행하라.

[대상]
PUB-01 메인 / PUB-06/07 교육과정 목록·상세 /

기존 PUB-11/12 공지도 전체 연결 관점에서 점검한다.

[할 일]
- 메인을 공통 상단 → 핵심 소개 → 주요/최근 공지 → 교육·프로그램 현황 → 서식 바로가기 → 공통 하단 순으로 구성한다.
- '내 전공에 AI를 더하다' 문구와 절제된 AI 연결 그래픽을 적용하되 공지·서식이 과도하게 아래로 밀리지 않게 한다.
- 교육과정은 수준별 소개, 프로그램은 유형별 소개를 보여 주고 상세 화면으로 연결한다. 진행 상태 배지는 만들지 않는다.
- 자료실은 서식 목록·분류·검색·수정일을 제공하고 상세에서 대상·작성 방법·기한·제출처·다운로드를 안내한다.
- 관련 교육 ↔ 공지 ↔ 서식 연결을 구성하며 비공개·삭제된 대상은 공개 링크에서 제외한다.
- 게시물 ID와 slug의 역할, 제목 변경 시 주소 유지 정책을 정리하고 이미 배포할 주소를 불필요하게 변경하지 않는다.
- 이미지가 없어도 텍스트로 핵심 정보를 확인할 수 있도록 한다.
- 검색 결과 없음, 파일 없음, 잘못된 상세 주소, 서버 오류를 적절히 안내한다.

[완료 기준]
공개 15개 화면 유형이 모두 DB 콘텐츠와 연결된다.
메인 → 교육 상세 → 공지 → 서식 → 파일 다운로드 흐름이 작동한다.
관리자 수정 결과가 별도 코드 수정 없이 공개 페이지에 반영된다.
각 상세 페이지 새로고침과 직접 접속이 동작한다.
```

## P-09. 콘텐츠 백업·복원 구현

```text
프로젝트 기준 및 진행기록을 읽고 09단계를 진행하라.
추가 관리자 메뉴를 늘리기보다 로컬 명령/스크립트로 내보내기와 복원을 제공하라.

[할 일]
- 게시물·교육정보·서식·FAQ·기본정보·메인 설정·참여 안내·관련 연결·파일 메타데이터·첨부파일을 함께 내보낸다.
- 문서화된 논리 데이터 형식(JSON 등), 스키마 버전, 파일별 해시/크기, 상대 저장키를 포함한다.
- 환경변수·비밀키·세션·관리자 비밀번호 해시는 일반 콘텐츠 이관 패키지에서 제외한다. 새 환경의 관리자는 별도 설정한다.
- SQLite를 사용한다면 실행 중 DB 파일만 단순 복사하지 말고 일관된 스냅샷/내보내기 또는 안전한 정지 절차를 사용한다.
- DB와 첨부파일이 같은 시점에 대응하도록 내보내기 동안 변경을 제한하거나 일관성 확보 방법을 마련한다.
- 가져오기는 기본적으로 빈 DB와 새 저장 폴더를 대상으로 한다. 기존 자료가 있으면 자동 덮어쓰지 않고 충돌을 보고한다.
- 패키지 경로 조작, 누락 파일, 잘못된 스키마, 중복 ID를 검사하고 실패 시 불완전 복원을 공개하지 않는다.
- 저장키와 콘텐츠 ID를 유지하여 환경의 절대경로 변경에도 링크를 복원한다.
- 로컬용 SQLite 스키마/덤프가 향후 D1에 그대로 들어간다고 가정하지 말고 호환 확인 항목을 문서화한다.

[완료 기준]
별도 빈 로컬 환경에서 내보내기 패키지를 복원한다.
콘텐츠 건수·본문·공개 여부·관련 링크·파일 해시가 원본과 일치하는지 확인한다.
복원 환경에서 관리자 재설정 후 편집과 공개 다운로드가 가능해야 한다.
```

이번 확인은 기존 실행 로그·복원 결과·Git 감사와 문서 대조다. P-10 서버 122/122와 신규 3/3, 브라우저 최초 67/69 후 영향받은 3건 재검 통과(최종 69개 고유 사례), P-11 새 폴더 재현/복원 통과 근거를 확인했다. 검증된 P-11 전달본과 비교해 코드·설정·테스트 등 문서 외 85파일의 SHA-256이 같았다. 이번에 앱·브라우저 전체 시험을 다시 실행한 것은 아니다.

**남은 확인:** 실제 한컴 HWP/HWPX 원본으로 업로드·다운로드/해시·비공개 차단·재시작/복원 시험이 필요하다. 실제 사용자 터미널의 키보드 Ctrl+C도 미검증이며 현재 재시작 증거는 소유 PID 종료 방식이다. 다른 PC·빈 설치 캐시·실물 모바일·다른 브라우저·운영 HTTPS는 확인 범위 밖으로 유지한다. 외부 Publish와 D1/R2 전환은 후속 작업이다.
