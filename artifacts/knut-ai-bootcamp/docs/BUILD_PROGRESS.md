### 남은 문제 / 미검증

- 최초 Node/npm 실행 불가 문제는 사용자 설치 후 재확인으로 해결했다. 아래 후속 기록에 버전과 확인 명령을 남겼다. 프로젝트 의존성·빌드·앱 실행 검증은 아직 필요하다.
- 웹 서버·화면·DB·인증·첨부·백업 기능 자체가 없으므로 실행, 빌드, 재시작 유지, 로그인, 업로드/다운로드, PC/모바일 검수는 모두 미검증이다.
- 공개·관리자 28개 화면 모두 미구현이다. 최종 로컬 완성을 선언하지 않는다.
- HWP/HWPX 정상 시험 원본, 공식 사업 콘텐츠·연락처·주소·로고가 제공되지 않았다. 필요한 시점에 실제 자료로 검증/입력하며 임의 작성하지 않는다.
- Git 추적 제외 정책은 설계만 했다. `.gitignore` 및 실제 추적 여부 검증은 P-02 이후 대상이다.
- 실제 의존성 버전·잠금 파일은 설치 후 고정한다. `better-sqlite3` Windows 설치와 브라우저 검수 수단은 해당 단계에서 확인한다.
- 운영 인증 공급자와 최종 게시물 DB는 미확정이다. D1은 후보이며 자동 이관을 보장하지 않는다.

## P-03 DB·콘텐츠 구조 — 2026-10-14

### 작업 기준과 보존

- 기준 원문의 P-03, 프로젝트 기준·화면 목록·진행기록과 현재 소스, README, 패키지·잠금 파일, 설정을 먼저 확인했다. AGENTS는 없으며 폴더는 여전히 Git 저장소가 아니다. 기존 프레임워크를 유지했다.

- 실제 데이터는 `var/db/bootcamp.sqlite`에 새로 생성했다. 기존 자료 삭제·DB 초기화·원격 저장소 선택·Git 초기화·외부 배포는 하지 않았다. 원본 MD/TXT 해시는 아래 P-01 값과 일치한다.

### 구현 내용

- `better-sqlite3 13.0.3`과 타입 `9.6.0`을 실제 설치하고 잠금 파일에 반영했다. 현재 Node `24.21.0`/Windows에서 제공 네이티브 바이너리와 SQLite `3.53.4` 동작을 확인했다. 전역 실행 정책·설치 스크립트 일괄 허용 설정을 바꾸지 않았다.
- 실제 파일 DB 연결에 외래키, WAL, 5초 busy timeout, FULL 동기화를 적용했다. 실행 서버는 기존 DB와 적용 이력을 확인하고 DB가 없거나 미적용이면 안내와 함께 종료한다. 시작할 때 생성·초기화·마이그레이션·seed를 반복하지 않는다.
- 공통 `contents`와 종류별 `program_details`, `resource_details`, `contact_details`, 관계/파일/메인/외부 링크, 관리자·세션 구조, 마이그레이션·seed 이력을 포함한 13개 테이블을 구현했다. 진행·모집 상태 필드는 없다. 서식의 대상·서류·작성법·기한·방법·제출처·문의처·연도도 저장한다.
- ID·종류·slug를 안정적으로 유지하고, revision으로 수정 충돌을 거부한다. 매개변수 질의, STRICT/FK/고유값/CHECK/종류 일치 제약을 적용했다. 콘텐츠·세부 정보·관계·파일 연결의 쓰기는 원자적이며 여러 질의로 구성한 읽기는 같은 스냅샷을 사용한다.
- 공개 조회 목록·상세·고정 안내·프로그램·메인은 실제 DB를 조회하고 초안/비공개 본문·관련 대상·메인 선택을 제외한다. 파일 응답에 저장키·해시·개인 PC 경로를 내보내지 않는다. 파일 정보 구조만 구현했으며 원본·다운로드 URL은 만들지 않았다.
- `db:migrate`는 순차 SQL·체크섬을 기록한다. 적용한 파일의 수정·누락·알 수 없는 이력을 거부하고, 대기 작업 전체를 트랜잭션으로 적용한다. 기존 DB의 변경 전에는 SQLite 백업 API로 WAL 내용까지 보존하는 사본을 만든 뒤 경로를 출력한다. 실패하면 전체 롤백한다.
- `db:seed`는 명백한 예시 9건을 별도로 한 번만 넣는다. `seed_runs`에 버전 키와 체크섬을 남겨 재실행 시 편집·삭제한 예시와 연결을 복원하거나 중복 생성하지 않는다. 최초 적용에서도 기존 동일 ID의 내용을 보존하고 ID/slug 충돌은 전체 거부한다. 기존 데이터에 새 seed를 넣을 때는 안전 사본을 먼저 만든다. 체크섬은 Windows CRLF/LF 차이를 정규화한다.
- `DB_PATH`, `UPLOAD_DIR`, `BACKUP_DIR`를 설정 가능하게 했다. 프로젝트 상대/절대 경로를 지원하며 실제 심볼릭 링크 대상까지 검사해 소스·공개·빌드 경로에 데이터를 두지 않는다. 화면용 API 호출을 분리했고 관리자 메인은 실제 DB 연결 여부를 표시한다.

### 구현 내용

- ADM-01 실제 로그인, ADM-02 관리 홈·사용자명·로그아웃, 로그인 외 모든 관리자 화면의 서버 세션 확인을 연결했다. 경로 이동·포커스·만료와 오류/재시도를 처리한다. 공개 API는 익명 조회를 유지한다.
- `admin:create`/`admin:reset`은 대화형 TTY에서 숨김 비밀번호·확인 입력을 받고 변경 전 SQLite 안전 사본을 만든다. 인수·환경변수·파이프 비밀번호를 사용하지 않으며 기본 관리자/고정 비밀번호/가입/계정관리 화면을 추가하지 않았다. 실제 작업 DB에는 관리자를 만들지 않았다.
- Node.js scrypt(N=32768/r=8/p=3)·무작위 salt·일정 시간 비교를 사용한다. 무작위 32바이트 세션 토큰의 해시만 SQLite에 저장하며 활성 관리자·기본 8시간 절대 만료를 매 요청 확인한다. 로그아웃/재설정은 기존 세션을 삭제한다.
- HttpOnly·SameSite=Lax 쿠키, 로그인 전 CSRF와 로그인 후 세션 CSRF, 정확한 Origin 검사, HTTPS Secure 설정 분리, DB에 유지되는 IP/아이디 로그인 시도 제한을 적용했다. 서버 내부 오류·비밀번호·세션 토큰을 JSON이나 로그에 노출하지 않는다.
- 모든 `/api` 변경 메서드와 `/api/admin` 조회에 공통 서버 검사를 적용했다. 관리자 상세 조회는 비공개를 허용하고 공개 API는 로그인 여부와 관계없이 공개 자료만 반환한다. 파일 경로는 실제 파일/콘텐츠 ID 연결·공개 여부를 검사한다.
- P-05에 배정된 콘텐츠 CRUD·파일 원본 기능은 이번에 추가하지 않았다. 미인증 401 → CSRF 실패 403 → 검증 통과 후 미구현 501을 구분한다. 운영에 없는 시험 전용 변경 경로에 동일한 운영 미들웨어를 붙여 실제 DB 수정 허용·차단을 검증했다.

### 남은 문제 / 완료 판정

- **판정: P-05 기능 구현 완료, 일부 검증 보류. 최종 완료 아님.** 프로젝트에 실제 한컴 작성 HWP/HWPX 원본이 없으므로 정상 원본 호환성은 확인하지 못했다. 확장자를 바꾼 텍스트·임의 ZIP은 거부 시험이며, 합성 CFB/HWPX는 검사 코드 경로 시험일 뿐 정상 한컴 문서 검증 증거가 아니다.
- 최종 판정에는 실제 HWP·HWPX 각 원본의 관리자 업로드 → 공개 다운로드 → 원본 해시/한글 파일명 일치 → 비공개 직접 URL 차단을 확인해야 한다. 실패하면 해당 구조·지원 정책을 확인해 수정하고 재검증한다. 개인정보 없는 시험 원본을 사용한다.
- PDF는 기본 구조, DOCX/HWPX는 ZIP/XML 구조, HWP는 HWP5 CFB 구조, 이미지는 디코딩 검사다. 악성코드 완전 탐지·모든 저작도구/암호화/구형 문서 호환성을 보장하지 않는다. 생성한 PDF/DOCX 시험은 저작도구에서 실제 문서를 열어 보는 수동 검수와 구분한다.
- 미연결 원본은 명시적 정리 대상이며 자동 만료 삭제하지 않는다. DB와 파일시스템은 단일 원자적 저장소가 아니므로 강제 전원 차단 등에서 남을 수 있는 비공개 잔여 파일도 총량에 포함한다. 전체 콘텐츠 이관/복원과 장애 복구 도구는 P-09 범위다.
- Windows·설치된 Chrome에서 검증했다. 실물 모바일·다른 OS/브라우저·운영 HTTPS/역방향 프록시·Replit/Cloudflare 배포는 미검증이다. Git 저장소가 없어 실제 추적 상태는 검증하지 못하며 제외 규칙만 유지했다.
